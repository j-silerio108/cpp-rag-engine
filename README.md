# CppRAGEngine

A local retrieval-augmented generation (RAG) engine: a brute-force vector search core written in modern C++ (C++23), a Python ingestion pipeline that generates real embeddings with a local ONNX model, and an MCP server that exposes the whole thing as a tool for Claude Code.

Everything runs locally. No API calls at query time — embeddings are generated by a model that runs on your own CPU, and the search itself is a compiled C++ binary.

## How it fits together

Two separate programs, in two different languages, that never call each other directly:

- **Ingestion (Python, run once per new document):** `tools/embed_documents.py` reads a folder of `.txt` notes, embeds each one with [`bge-small-en-v1.5`](https://huggingface.co/BAAI/bge-small-en-v1.5) (via [`fastembed`](https://github.com/qdrant/fastembed), ~130MB, ONNX runtime, no PyTorch), and writes everything to `data/documents.csv`.
- **Query (C++, run on every search):** `rag_cli.exe` loads that CSV, ranks stored documents against a query vector by cosine similarity, and returns the top-k matches.

`data/documents.csv` is the *only* coupling between the two — a plain CSV file, not a shared library or IPC channel. Both sides must embed text with the same model, or the similarity scores are meaningless.

```
notes/*.txt --> embed_documents.py --> data/documents.csv --> rag_cli.exe --> ranked results
                (fastembed, local)                            (cosine similarity, C++)
```

An [MCP server](mcp_server/server.py) wraps this: it embeds an incoming query in-process and calls `rag_cli.exe --json` as a subprocess, so the C++ engine is still what actually ranks results — the server just gives it a new way to be asked a question (stdio/MCP instead of argv).

## Design

- `Index` ([include/ragengine/index.hpp](include/ragengine/index.hpp)) is an abstract interface with one method, `search()`. `BruteForceIndex` is the only implementation today, but the interface exists so a smarter index (e.g. an approximate-nearest-neighbor structure) could be swapped in later without touching any caller.
- `cosine_similarity` ([include/ragengine/similarity.hpp](include/ragengine/similarity.hpp)) is a template constrained by a C++20 concept (`FloatVector`), not hardcoded to `std::vector<float>`.
- Ranking uses `std::ranges::partial_sort` with a projection, not a hand-rolled loop.
- No raw `new`/`delete` anywhere — ownership is `std::unique_ptr<Index>` in `main.cpp`, and `std::vector<Document>` owning its data by value elsewhere.
- `rag_cli.exe` is statically linked on MinGW (`-static`), so it has no runtime dependency on `libstdc++`/`libgcc`/`libwinpthread` DLLs — it needs to run correctly no matter what process launches it (a dev shell, or an MCP client).

## Building

Requires a C++23 compiler, CMake 3.21+, and Ninja or Make. On Windows, [MSYS2](https://www.msys2.org/)'s MinGW-w64 toolchain works well:

```bash
cmake -G Ninja -B build
cmake --build build
```

Run the tests ([Catch2](https://github.com/catchorg/Catch2), pulled via CMake `FetchContent`):

```bash
ctest --test-dir build
```

## Generating embeddings

```bash
python -m venv venv
venv/bin/pip install fastembed
venv/bin/python tools/embed_documents.py --input-dir data/notes --output data/documents.csv
```

## Querying

```bash
venv/bin/python tools/embed_query.py "what should I do with my dog" > query.vec
./build/rag_cli data/documents.csv "$(cat query.vec)" 3
```

Add `--json` for machine-readable output (`[{"id":.., "score":.., "text":..}, ...]`).

## MCP server

`mcp_server/server.py` exposes one tool, `search_notes(query, top_k=3)`, over the Model Context Protocol. Point an MCP client at it (e.g. via a project's `.mcp.json`):

```json
{
  "mcpServers": {
    "ragengine": {
      "command": "/path/to/venv/bin/python",
      "args": ["mcp_server/server.py"]
    }
  }
}
```

## Project layout

```
include/ragengine/   Public headers (Document, Index, BruteForceIndex, similarity, CSV loader)
src/                  Implementations + the CLI entry point (main.cpp)
tests/                Catch2 unit tests
tools/                Python embedding scripts (ingestion + single-query)
mcp_server/           MCP server wrapping the engine
data/                 Sample notes and the generated embeddings CSV
```
